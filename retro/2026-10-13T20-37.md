# Retro: youtube-tracker story 2, the hourly upload pass

The story shipped as written, and its criteria never had to change during the build.
Time went to a wrong test that was already locked, to a mutation check that passed while broken, and to credentials no file recorded.
The highest-value fix is to make the mutmut step of `./check --full` fail when mutmut fails.

## Context

* **Story:** [youtube-tracker issue 2](http://gitea.local:3000/dave/youtube-tracker/issues/2), "Tracker records a new upload within an hour".
* **Pull request:** [youtube-tracker pull request 14](http://gitea.local:3000/dave/youtube-tracker/pulls/14), merged as `dda629d` on 2026-10-13.
* **Workflow:** the SDLC story skill, from interface stubs through failing tests, the test-challenger, implementation, review, and the pull request.
* **Outcome checks:** scheduled for 21:41 on 2026-10-13 and 02:17 on 2026-10-14, still pending at the time of writing.

## Mistakes the agent made

These are errors in the agent's own work.

* **Locked a test before checking the tool:** the review fix test required `deploy/crontab` in mutmut's `also_copy`.
  mutmut copies a file entry without creating its parent directory, so that entry can never work.
  The test was already locked, so correcting it needed the user to approve an unlock.
  One grep of mutmut's copy code beforehand would have shown the right entry, `deploy`.
* **Guessed hostnames with a password:** the agent tried the reader password against `warehouse` and `warehouse.local` before asking for the host.
  It should have asked first.
  It had also proposed the `ingest_reader` role, while the deployed tracker uses `feeds_automation`.
* **Added a dependency too early:** `defusedxml` went into the interface commit before any code imported it.
  deptry failed, and the dependency had to be backed out and added again with the implementation.
* **Staged with `git add -A`:** the guard hook blocks a blanket add, so the commit had to be retried with named paths.
* **Skipped reading the challenger's tests:** the test-challenger added a `# type: ignore` and 2 `# noqa: SLF001` lines, against AGENTS.md's rule never to silence a check.
  The agent moved on without reading the file, so review caught them, and removing them needed a second unlock.

## Tooling and process friction

These problems came from the repository, the hooks, or the harness.

* **Mutation check passes when mutmut fails:** the mutmut step of `./check --full` ends with `|| echo "mutmut did not finish"`, so the check exits 0.
  A missing file in mutmut's copy stayed hidden until all 3 review agents found it separately.
  This gap is still in the repository.
* **Test Postgres servers leak:** mutmut runs and the reviewers' test runs left dozens of pytest-postgresql servers running, and they used up shared memory.
  32 mutants crashed and remain unchecked.
  A rerun of only those mutants failed on mutmut's argument handling, and the agent did not investigate further.
* **Review agents cannot write findings files:** the harness refused each agent's `findings-<n>.md` write, and it also denied writes to the `.git` directory.
  The agent copied 3 reports into `/tmp/yt2-review/` by hand.
* **Guard hook misparses commands:** it read the `2` in `uv add defusedxml 2>&1` as a package name.
  It also blocked a commit chained with `rm -rf mutants` with a message about locked tests, while the same commit run alone went through.
* **Credentials were undocumented:** no file named the Gitea token or the warehouse host.
  The agent also tried the `-s` and `-a` flags of `security find-generic-password` before finding the token by its label with `-l`.
* **gitleaks is not installed:** `./check --full` stopped at gitleaks, so the branch was never scanned for secrets.

## What worked

* **Concrete criteria:** each example named real values, so every test came straight from the story and the code kept the shape of its first version.
* **Test-challenger:** it added 13 tests for real gaps, among them the installed command's handling of `--hourly`, the crontab line, and ids listed in 2 feeds.
* **Review and verify:** the 3 reviewers produced 14 candidate rows, and verification kept 5 with evidence, which kept the follow-up small.
