# Markdown and tools: settings for readable text

Research date: 2026-10-02.
Scope: iTerm2, VS Code (editor, terminal, Markdown preview), Neovim, Obsidian with the Minimal theme, Claude Code's terminal output, and the Markdown source that feeds them.
Method: settings keys come from official docs or from each project's source code, fetched on the research date.
Current values come from the user's own config files, read without changes.
A claim marked **[unverified]** comes from a search snippet, an estimate, or memory, not from a page that was fetched.

## 1. What the current setup does today

* **Obsidian prose is in Fira Code:** `textFontFamily` in `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/notes/.obsidian/appearance.json` is `"FiraCode Nerd Font,Atkinson Hyperlegible Next"`. Browsers pick a font one character at a time and try the next family only when the first lacks a glyph ([MDN font-family](https://developer.mozilla.org/en-US/docs/Web/CSS/font-family)). Fira Code has every Latin letter, so Atkinson Hyperlegible Next only draws characters that Fira Code lacks. Put `Atkinson Hyperlegible Next` first to get it for prose.
* **VS Code terminal font is missing:** `terminal.integrated.fontFamily` is `"MesloLGS NF"` in `~/Library/Application Support/Code/User/settings.json`. No MesloLGS font is registered on this Mac (`system_profiler SPFontsDataType` and Spotlight return nothing for it). The terminal falls back to another monospace font **[unverified which one]**. Set it to `"FiraCode Nerd Font Mono"`, which is installed, or install MesloLGS NF.
* **Claude Code prose is capped at 80 columns:** `~/.claude/settings.json` has `"maxProseWidth": 80`. This wraps paragraphs, headings, lists and blockquotes at 80 columns, while tables and code blocks keep the full terminal width ([settings reference](https://code.claude.com/docs/en/settings-reference#maxprosewidth)). The theme is `"dark-daltonized"`, the colorblind-friendly dark theme ([settings reference](https://code.claude.com/docs/en/settings-reference)).
* **iTerm2 grey text is below WCAG AA:** in the default profile "Dave Profile", dark-mode foreground `#DCDCDC` on background `#15191F` is 12.8:1, but ANSI color 8 (bright black) `#686868` on that background is 3.2:1 (computed from the `com.googlecode.iterm2` plist with the WCAG luminance formula). WCAG AA asks for 4.5:1 ([VS Code `terminal.integrated.minimumContrastRatio` description, which cites WCAG](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts)). `Minimum Contrast` is 0, so iTerm2 does not correct it ([iTerm2 colors](https://iterm2.com/documentation-preferences-profiles-colors.html)). Programs that print grey or "dim" text often use ANSI 8 **[unverified for Claude Code]**.
* **Neovim splits words at the wrap point:** `~/.config/nvim/init.lua` (kickstart.nvim) sets `breakindent` but not `linebreak`. With `wrap` on and `linebreak` off, Neovim breaks a long line in the middle of a word ([options.txt](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt)). No Markdown rendering plugin is installed, and the colorscheme is `tokyonight-night`, while VS Code uses Catppuccin Mocha.
* **The VS Code Markdown preview has no line-length cap:** the preview stylesheet sets `padding: 0 26px` on `body` and no `max-width` ([markdown.css](https://github.com/microsoft/vscode/blob/main/extensions/markdown-language-features/media/markdown.css)). Lines run the full width of the preview pane. A half-width pane on a 2560-point-wide screen is about 1250 px and holds well over 100 characters at 16 px **[unverified estimate]**.
* **iTerm2 cell size:** FiraCode Nerd Font Mono has 1950 units per em, an advance width of 1200 units and ascent plus descent of 2400 units (read from the installed font file with fontTools). At 18 pt with `Horizontal Spacing` and `Vertical Spacing` at 1.0, each cell is about 11.1 pt wide and 22.2 pt tall, a line height of 1.23. A full-width window on a 2560-point-wide desktop holds about 230 columns **[unverified: assumes the default 5K scaled resolution of 2560 × 1440 points]**.
* **Obsidian line width:** the Minimal Theme Settings plugin stores `lineWidth: 40`, `lineWidthWide: 50`, `maxWidth: 88`, `lineHeight: 1.5`, `textNormal: 16` and `readableLineLength: true` in `.obsidian/plugins/obsidian-minimal-settings/data.json`. The plugin writes `lineWidth` as `--line-width: 40rem` ([styles.ts](https://github.com/kepano/obsidian-minimal-settings/blob/master/src/utils/styles.ts)). At 16 px per rem that is 640 px, which fits about 65 Fira Code characters or about 73 Atkinson Hyperlegible Next characters (average width 544/1000 em, read from the font file) **[unverified: assumes a 16 px root size]**. Both counts sit inside the 45 to 90 character range in [Practical Typography](https://practicaltypography.com/line-length.html).

The Markdown extension sets `"[markdown]": { "editor.wordWrap": "on" }` by default ([package.json](https://github.com/microsoft/vscode/blob/main/extensions/markdown-language-features/package.json)). Set `"[markdown]": { "editor.wordWrap": "bounded", "editor.wordWrapColumn": 80 }` to cap Markdown source at 80 columns.

* **Theme colors and contrast:** `workbench.colorTheme` (yours is `"Catppuccin Mocha"`), `workbench.colorCustomizations`, `editor.tokenColorCustomizations` and `editor.semanticTokenColorCustomizations`; scope an override to one theme with `"[Catppuccin Mocha]": {...}`. `window.autoDetectHighContrast` switches to a high-contrast theme when macOS does ([VS Code themes](https://code.visualstudio.com/docs/configure/themes)).
* **Bold and italic:** come from the theme's token colors; override them through `editor.tokenColorCustomizations` ([VS Code themes](https://code.visualstudio.com/docs/configure/themes)).
* **Ligatures:** `editor.fontLigatures` takes a boolean or a CSS `font-feature-settings` string ([editorOptions.ts](https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts)). Yours is true.

### Neovim (`~/.config/nvim/init.lua`)

* **Font family, size, weight, letter spacing, ligatures:** in a terminal, Neovim uses the terminal's font, so iTerm2 sets all of them. `guifont` and `linespace` apply only to GUI front ends ([options.txt](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt)).
* **Line height:** set by iTerm2 `Vertical Spacing` for terminal Neovim; `linespace` adds pixel rows in GUIs only ([options.txt](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt)).
* **Wrap:** `wrap` (default on) wraps long lines on screen without changing the buffer; `linebreak` (default off) breaks at a `breakat` character instead of mid-word; `breakindent` (default off; on in your config) indents wrapped lines to match; `breakindentopt` tunes that indent; `showbreak` prints a marker at the start of wrapped lines ([options.txt](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt)).
* **Max line width:** `textwidth` (default 0, off) inserts real line breaks while typing; `colorcolumn` highlights columns and accepts `+1` for "one past textwidth" ([options.txt](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt)). Neovim has no option to soft-wrap at a column narrower than the window **[unverified: from memory]**; narrow the window or use a plugin to get a reading width.
* **Concealing Markdown syntax:** `conceallevel` 0 to 3 hides syntax characters; `concealcursor` sets which modes also conceal the cursor line ([options.txt](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt)).
* **Theme colors and contrast:** `vim.cmd.colorscheme` (yours is `tokyonight-night`); `termguicolors` turns on 24-bit color and Neovim turns it on when the terminal supports it ([options.txt](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt)).
* **Rendered Markdown, render-markdown.nvim:** needs Neovim 0.9 or later (0.10 recommended), the `markdown` and `markdown_inline` treesitter parsers (already in your treesitter list) and a Nerd Font; install with lazy.nvim as `{ 'MeanderingProgrammer/render-markdown.nvim', dependencies = { 'nvim-treesitter/nvim-treesitter', 'nvim-mini/mini.icons' }, opts = {} }` ([render-markdown.nvim](https://github.com/MeanderingProgrammer/render-markdown.nvim)).
* **render-markdown.nvim options:** `heading.width` and `code.width` (`'full'` or `'block'`), `code.left_pad`, `paragraph.left_margin` (a float below 1 is a share of the window), `pipe_table.cell` (`overlay`, `raw`, `padded`, `trimmed`), `pipe_table.wrap = true` to wrap cells so wide tables fit the window, `render_modes`, `anti_conceal` to show raw text on the cursor line, and `win_options.conceallevel.rendered = 3` ([render-markdown.nvim](https://github.com/MeanderingProgrammer/render-markdown.nvim)). It renders both GitHub and Obsidian callouts ([render-markdown.nvim](https://github.com/MeanderingProgrammer/render-markdown.nvim)).
* **Rendered Markdown, markview.nvim:** needs Neovim 0.10.3 or later, recommends `nowrap` and Nerd Fonts, offers hybrid mode (edit and preview in place) and a split view, and should not be lazy-loaded (`lazy = false`) ([markview.nvim](https://github.com/OXY2DEV/markview.nvim)).

## 3. Markdown in a terminal

* **What Claude Code renders:** the changelog records rendering for tables as a bordered grid with cell wrapping, fenced code with syntax highlighting (highlight.js 11), code blocks without a language colored like inline code, task-list checkboxes, strikethrough, blockquotes as italic text with a continuous left bar, horizontal rules, nested lists with a hanging indent on wrapped items, and links as OSC 8 hyperlinks or as `label (url)` where hyperlinks are not supported ([changelog](https://code.claude.com/docs/en/changelog)).
* **Headings in Claude Code:** the docs do not describe how headings look; they show as bold text without `#` markers **[unverified: from observation]**.
* **Tables in Claude Code:** tables keep the full terminal width even when `maxProseWidth` is set ([settings reference](https://code.claude.com/docs/en/settings-reference#maxprosewidth)). In a narrow terminal, tables switch to a stacked layout of `Header: value` lines ([changelog](https://code.claude.com/docs/en/changelog)). Tables over 200 rows show the first 200 and a "… N more rows not shown" line ([troubleshooting](https://code.claude.com/docs/en/troubleshooting)). The docs do not give the column count at which the stacked layout starts; narrow an iTerm2 window step by step to find it.
* **Fixed table bugs that show what breaks:** tables overflowing and wrapping their right border, a pipe inside an inline code span breaking a table, stale bordered renders left in scrollback while streaming, and `&nbsp;` printed as text ([changelog](https://code.claude.com/docs/en/changelog)).
* **glow:** `glow -w 60` wraps at 60 columns, `-s dark|light|auto` or a JSON style file picks the style, `-p` pipes through a pager (`less -r` by default), and the config file accepts `width: 80` ([glow](https://github.com/charmbracelet/glow)).
* **mdcat:** the original repository is archived and points to a maintained fork; it does not support footnotes or inline markup and text wrapping in table cells, and it adds iTerm2 jump marks for headings ([mdcat](https://github.com/swsnr/mdcat)).
* **Rich:** `rich.markdown.Markdown` centers `h1` and left-aligns other headings, draws tables with `box.SIMPLE`, and takes `code_theme` (default `"monokai"`), `justify`, `hyperlinks` and `inline_code_lexer` ([rich/markdown.py](https://github.com/Textualize/rich/blob/master/rich/markdown.py)).
* **How width affects tables:** a terminal table is as wide as its widest cells plus borders. When the sum passes the window width, the renderer either wraps cells (Claude Code, render-markdown.nvim with `pipe_table.wrap`), stacks rows (Claude Code in narrow windows), or lets lines wrap at the terminal edge, which breaks the grid (mdcat has no cell wrapping) ([changelog](https://code.claude.com/docs/en/changelog), [render-markdown.nvim](https://github.com/MeanderingProgrammer/render-markdown.nvim), [mdcat](https://github.com/swsnr/mdcat)).
* **Long lines:** prose rewraps to the window or to `maxProseWidth`. Code blocks keep their lines, so a long line in a code block wraps at the terminal edge or runs past it **[unverified for Claude Code]**. Long URLs stay clickable across wrapped lines in terminals with OSC 8 ([changelog](https://code.claude.com/docs/en/changelog)).
* **Nested lists:** Claude Code fixed misalignment at depth 3 and deeper ([changelog](https://code.claude.com/docs/en/changelog)). Keep lists to two levels so older renderers stay aligned.

## 4. Markdown source readability

* **Hard wrap:** break lines at a fixed column such as 80. The source reads well in any editor without wrap, but an edit near the start of a paragraph reflows every later line, so the diff marks the whole paragraph changed ([sembr.org](https://sembr.org/)). GitHub turns newlines into line breaks in issues, pull requests and discussions, so hard-wrapped text pasted there shows ragged breaks ([GitHub formatting](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)).
* **Soft wrap:** write one paragraph per line and let the editor wrap it. One changed word marks the whole paragraph changed in a line diff **[unverified: follows from line-based diff]**. It needs wrap in every editor: VS Code wraps Markdown by default ([package.json](https://github.com/microsoft/vscode/blob/main/extensions/markdown-language-features/package.json)), Neovim needs `linebreak` to avoid mid-word breaks ([options.txt](https://github.com/neovim/neovim/blob/master/runtime/doc/options.txt)), and markdownlint MD013 flags the long lines unless turned off ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **Semantic line breaks:** break after every sentence (MUST), after independent clauses (SHOULD), never inside a hyphenated word, with a recommended maximum of 80 characters ([sembr.org](https://sembr.org/)). A change to one sentence then changes one line in the diff ([sembr.org](https://sembr.org/)). The breaks do not change rendered HTML because CommonMark renders a single newline as a soft break, which displays as a space ([CommonMark 6.8](https://spec.commonmark.org/0.31.2/)). They do show as breaks in GitHub comments ([GitHub formatting](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)), in Obsidian reading view when "Strict line breaks" is off ([Obsidian settings](https://obsidian.md/help/settings)), and in the VS Code preview when `markdown.preview.breaks` is true ([package.json](https://github.com/microsoft/vscode/blob/main/extensions/markdown-language-features/package.json)).
* **Hard line breaks:** end a line with two spaces or a backslash to force `<br>` ([CommonMark 6.7](https://spec.commonmark.org/0.31.2/)). Prefer the backslash because trailing spaces are invisible; markdownlint MD009 allows exactly `br_spaces` (default 2) trailing spaces ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **MD001:** increment heading levels by one; skipped levels confuse readers, especially with assistive technology ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **MD013:** line length, default 80, with separate `heading_line_length` and `code_block_line_length`, switches for `code_blocks`, `tables` and `headings`, and an exception for lines with no whitespace past the limit, such as long URLs ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)). Turn off `tables` when tables are allowed to be wide.
* **MD004, MD007, MD029, MD030:** use one bullet marker per document, indent nested bullets 2 spaces so nested content lines up with the parent text, and number ordered lists `1.` throughout or in order ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **MD022, MD031, MD032, MD058:** put blank lines around headings, fenced code, lists and tables; some parsers, including kramdown, do not parse them otherwise ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **MD012, MD009, MD047:** no runs of blank lines, no stray trailing spaces, one newline at end of file ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **MD024, MD025, MD026, MD036, MD041:** no duplicate headings, one top-level heading, no trailing punctuation in headings, no bold line used as a heading, and an `h1` on the first line ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **MD040, MD046, MD048:** give every fenced block a language and use one code-block and fence style ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **MD055, MD056, MD060:** use one pipe style, keep the same column count in every row (extra cells are dropped), and optionally align columns ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **MD059:** write link text that describes the target ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **CommonMark quirk, list continuation:** a list item's later lines must be indented by the marker width plus the spaces after it (W + N), so `1.` and `10.` items need different indents ([CommonMark 5.2](https://spec.commonmark.org/0.31.2/)).
* **CommonMark quirk, interrupting a paragraph:** an ordered list can start right after a paragraph line only if it begins at `1`; an indented code block and a setext heading cannot interrupt a paragraph, so they need a blank line before them ([CommonMark](https://spec.commonmark.org/0.31.2/)).
* **CommonMark quirk, lazy continuation:** a line without `>` after a blockquote line still joins the quote's paragraph ([CommonMark 5.1](https://spec.commonmark.org/0.31.2/)). Two quotes separated only by a blank line merge in some parsers (MD028) ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)).
* **GFM tables are an extension:** a table cannot contain block elements, ends at the first blank line, and needs `\|` to put a pipe in a cell, including inside code spans ([GFM spec](https://github.github.com/gfm/)).

## 5. Structure that renders well in GitHub, VS Code, Obsidian and a terminal

* **Heading depth:** use `#` once for the title and `##` and `###` below it. GitHub builds an outline from headings ([GitHub formatting](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)), and markdownlint MD001 and MD025 enforce the order ([markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)). Deeper levels add little visual difference in a terminal **[unverified]**.
* **Table width:** keep tables to three or four short columns. Claude Code wraps cells and then stacks rows as width runs out ([changelog](https://code.claude.com/docs/en/changelog)), Obsidian with Minimal confines tables to the line width unless a `table-wide`, `table-max` or `table-100` class is set ([Minimal block width](https://minimal.guide/features/block-width)), and GitHub scrolls wide tables sideways **[unverified]**.
* **When tables wrap badly:** cells with sentences, long unbroken tokens such as paths or URLs, and inline code containing `|` ([changelog](https://code.claude.com/docs/en/changelog), [GFM spec](https://github.github.com/gfm/)). Use a bullet list for sentence-length comparisons; Claude's own Slack formatting changed to do that ([changelog](https://code.claude.com/docs/en/changelog)).
* **Code-block language tags:** tag every fence (`bash`, `json`, `lua`, `text`). Tags drive syntax highlighting (MD040, [markdownlint](https://github.com/DavidAnson/markdownlint/blob/main/doc/Rules.md)), render-markdown.nvim shows a language icon from them ([render-markdown.nvim](https://github.com/MeanderingProgrammer/render-markdown.nvim)), and Claude Code colors untagged blocks like inline code ([changelog](https://code.claude.com/docs/en/changelog)).
* **Callouts:** GitHub supports `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` and `[!CAUTION]`, advises one or two per article, and does not allow nesting ([GitHub formatting](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)). Obsidian uses the same `> [!type]` form with more types, aliases (`important` is an alias of `tip`, `caution` of `warning`), folding with `+` or `-`, and nesting ([Obsidian callouts](https://obsidian.md/help/callouts)). render-markdown.nvim renders both ([render-markdown.nvim](https://github.com/MeanderingProgrammer/render-markdown.nvim)). The VS Code preview and plain terminals show them as blockquotes with the literal `[!NOTE]` text (see section 2). Use the five GitHub types without nesting or folding when a file must work everywhere.
* **Emoji:** GitHub converts `:shortcode:` emoji ([GitHub formatting](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax)); other renderers show the shortcode text **[unverified]**. Terminals need agreement on emoji width; iTerm2's "Use Unicode Version 9+ Widths" exists for that ([iTerm2 Text](https://iterm2.com/documentation-preferences-profiles-text.html)). Skip emoji in tables, where a width mismatch shifts the borders **[unverified]**.
* **Nerd Font icons:** these glyphs come from patched fonts ([Nerd Fonts](https://github.com/ryanoasis/nerd-fonts)), so they show only where the reader's font includes them; on GitHub or another machine they show as empty boxes **[unverified: inference]**. Keep them out of shared documents.

## 6. Font families with a monospace and a prose member

* **Atkinson Hyperlegible Next and Mono:** Next has seven weights from Light to ExtraBold with italics; Mono is a variable-weight monospace "inspired by" Atkinson Hyperlegible, built for scanning tables and code; both cover over 150 languages and are free for personal and commercial use ([Braille Institute](https://www.brailleinstitute.org/freefont/)). The page does not call them a designed pair ([Braille Institute](https://www.brailleinstitute.org/freefont/)). Next is installed here; Mono is not. The Nerd Font build of Mono is named "AtkynsonMono Nerd Font" because of a reserved font name ([Nerd Fonts](https://github.com/ryanoasis/nerd-fonts)).
* **IBM Plex:** Sans, Sans Condensed, Serif and Mono, all with true italics, under the OFL ([IBM Plex](https://github.com/IBM/plex)). Nerd Font build: "BlexMono Nerd Font" ([Nerd Fonts](https://github.com/ryanoasis/nerd-fonts)). None of Plex is installed here.
* **iA Writer Mono, Duo and Quattro:** modified from IBM Plex ([iA-Fonts](https://github.com/iaolo/iA-Fonts)). Mono gives every letter one width, Duo gives `M` and `W` more room, and Quattro uses four widths; all keep wide word spacing and monospaced punctuation ([iA](https://ia.net/topics/a-typographic-christmas)). Duo or Quattro suits prose in Obsidian when a typewriter look is wanted. Nerd Font build: "iM-Writing Nerd Font" ([Nerd Fonts](https://github.com/ryanoasis/nerd-fonts)).
* **Fira:** Fira Code is based on Fira Mono and adds ligatures for sequences such as `->` and `<=` ([Fira Code](https://github.com/tonsky/FiraCode)). Its prose partner is Fira Sans from the same Mozilla project **[unverified: not fetched]**. Fira Code ships a Retina weight between Regular and Medium ([Fira Code](https://github.com/tonsky/FiraCode); the "between" placement is **[unverified]**).
* **Measured metrics on this Mac:** FiraCode Nerd Font Mono has an x-height of 0.54 em and a character width of 0.615 em; Atkinson Hyperlegible Next has an x-height of 0.50 em and an average width of 0.54 em (read from the installed font files with fontTools).
* **Nerd Font variants:** the default patched font has double-width icons; "Nerd Font Mono" makes icons single-width so every glyph fits one cell; "Nerd Font Propo" keeps proportional icon widths ([Nerd Fonts font-patcher options](https://github.com/ryanoasis/nerd-fonts)). Use the Mono variant (`FiraCodeNFM`) in terminals, as iTerm2 does now. Use the Propo or default variant in GUI text where icons may be wider ([Nerd Fonts](https://github.com/ryanoasis/nerd-fonts)).
