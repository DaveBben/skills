- Work carefully: first list the behaviours and edge cases this change must handle, write failing tests for them and commit those tests, then implement until they pass. Before you finish, have a fresh subagent review the diff for bugs, missed edge cases and weak tests, fix what it confirms, and run the full test suite.
- After committing the failing tests, record them as accepted: `git config branch.$(git branch --show-current).redCommit $(git rev-parse HEAD)`. A commit that changes an accepted test file is refused. A test you cannot satisfy for a reason that holds against the code is a stop: report the test and the reason, and make no change to it.
