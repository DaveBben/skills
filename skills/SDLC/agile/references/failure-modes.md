# Failure Modes

All three are one failure at different altitudes: a decision that belonged to the user arrived from an artifact instead. When working inside a constraint, ask whether it was chosen or inherited.

* **Developer-written cards.** The plan lists what the agent could see, not what the user wants. Cause: the agent named the slices instead of estimating and splitting the user's cards. Tell: slice titles name mechanisms or read like tasks.
* **Inherited scope.** Every slice shipped, nothing about the user's day changed. Cause: a spike's boundary became the project's boundary, or the delivering work sits behind a repo edge with no slice. Tell: the plan is precise about internals and silent about the user's day.
* **Unowned code.** Individually defensible additions nobody chose, accumulating into a shape the user cannot describe. Unrequested code is free to produce and unchanged in cost to own.
* **Unowned correctness.** All green, still not what was wanted. Two causes: a requirement with no test, fixed by mapping slices to tests in both directions; and a passing suite that never encoded the thing that matters, which only observing the shipped behaviour catches.
