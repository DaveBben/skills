# Step: set up

A story's **red commit** holds its failing tests and stubs only, made before any code by the red-commit command `AGENTS.md` records.

* **First story of a feature with several stories: clear the way once.** Ask one question: may the loop push branches named `story/{slug}/*` and adopted ones, rebase them with `--force-with-lease`, open and update their pull requests, and write to the epic's issues, for this feature. Have a `worker` record the answer on the header's `Context:` line. Anything wider (other pull requests, other branches) is asked when it comes up, naming exactly what it covers. Check from the repository and CI config that each repository on `Repositories:` deploys to production from main by a command in the repository, and that the feature acceptance test can run without manual steps; tell the user each gap once, as a story or as a risk.
* **Ready?** Re-read each blocker from the tracker through the `lookup` agent and confirm it merged into the story's base, and read the base's head now. A blocker unmerged, or a grant a plan or ADR records as denied, parks the story before any agent runs.
* **Work already begun.** Have the `lookup` agent look up the story's issue key among open branches and pull requests on the code host; skip this when the host is unreachable. A pull request the user authored is theirs: run `story.sh next adopt` and follow it in place of the next item. Another person's: the story waits for it. Say which in one line.
* **Cut the branch,** unless the story's worktree exists. In each repository the story changes, run `story.sh start {slug} {key} {short-name}` (the short name is two or three words of its title), finding each clone from `Repositories:` and cloning one that is missing. Have a `worker` set the issue In Progress. For an epic's first story, the user's feature acceptance test is committed on the branch first, or the story parks. When the story changes more than one repository, the called repository's pull request merges first.
* **Launch the `setup` agent** in the foreground, given the issue key, the worktree path, the path of `scripts/story.sh` and the header's `Outcome:`, `Not doing:`, `Constraints:`, `Context:` and `Decided:` lines. It writes the criteria, the test table, the failing tests and the red commit, writes the card to `card.md` in the worktree's git directory, and returns its path, the criteria and its questions.

When it returns, run `story.sh next criteria`.
